### UUID、checksum 和向量主键

- 数据库 id：本地记录主键。GitHub 远程 ID、Issue/PR 的 number 分别保存，用途不同。
- source_id：原始来源对象的标识，一个源文件可以对应多条 Document。
- chunk_id：切片的稳定内容/位置标识，不能直接当作 SQL Document.id。
- checksum：源文件内容指纹，用于重复或变更判断，不是数据库主键。
- Milvus pk：沿用 Document.id。替换旧片段时重新插入 Document，主键通常会改变；来源标识可以保持。

### SQL 事务与 Milvus

```text
准备文本 → 生成/校验向量 → 创建 Document
                                ↓
                      SQL flush：得到本地主键
                                ↓
                      写入 Milvus：沿用该主键
                                ↓
                      SQL commit：提交关系库事务
```

flush 不等于 commit。Milvus 写入失败会向上传播，阻止正常走到后面的 SQL 提交；但 SQL 与 Milvus 不共享一个事务，回滚 SQL 不会自动撤销已完成的向量写入。

### 索引和混合检索的实际配置

- Milvus 集合当前创建方式是 AUTOINDEX + COSINE，没有在这里手工设置 HNSW 的 M/efConstruction/efSearch。
- fulltext 分支从 SQL 取文本，在 Python 中进行 BM25；不要等同 PostgreSQL 自己维护的全文索引。
- hybrid 合并向量与关键词候选；Milvus 不可用时可以保留关键词分支。纯 vector 模式失败仍需报错。
- 检索分数和重排分数不是答案正确概率；候选筛选后仍需根据证据生成并核对引用。
